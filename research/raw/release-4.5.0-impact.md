### FIX-NOW-WRONG

1. `aur-sudo-password-prompt-mid-omarchy-update` (pacman-aur, corrected). #17000 (commit e9eeba4e) and #16568 (commit 24f59da2). #17000's message: "Omarchy commands revoked sudo's timestamp on entry and exit and authenticated through a sudo -N wrapper ... Ship timestamp_timeout=10, drop the revocation and the wrapper, and keep omarchy update's single authorization and keepalive." `bin/omarchy-update-aur-pkgs` passes no `--sudo` or `--sudoloop=false`, and the update's background `sudo -n true` keepalive runs until after `omarchy-update-boot`, which follows AUR. `etc/sudoers.d/omarchy-sudo-timeout` is `Defaults timestamp_timeout=10`. Affected sentences: "AUR then runs last with `yay --sudo <no-update wrapper> --sudoloop=false`, and the wrapper is `sudo -N`, which never writes a timestamp. So on that code every sudo call yay makes prompts, by design", "the extra prompts during the AUR step are the intended security boundary, and the updater passes `--sudoloop=false`", "Do not raise `timestamp_timeout` globally" (Omarchy now does), and the audit_note's "Omarchy ships only `passwd_tries=10` and does not change timestamp_timeout". On 4.5.0 the AUR step should not prompt at all. Confirmed.

2. `omarchy-sudo-passwordless-grants-root-to-every-process` (security, corrected). `bin/omarchy-sudo-passwordless` (623 changed lines, #9457 and #14435). `rule_file()` names the grant `/etc/sudoers.d/99-omarchy-nopasswd-<numeric uid>` and a new permanent grant `/etc/sudoers.d/99-omarchy-permanent-nopasswd-<uid>`. A temporary rule now reads `<user> ALL=(ALL) NOTAFTER=<UTC> NOPASSWD: ALL`, so sudo itself refuses it after the deadline, across suspend. Run with no argument and no active grant, it offers `gum choose` "15 minutes", "1 Hour", "1 Day", "Permanently". `--disable` is new. `etc/tmpfiles.d/omarchy-nopasswd-sudo.conf` still removes only `99-omarchy-nopasswd-*`, so a permanent grant survives reboot by design. New `default/libalpm/hooks/05-omarchy-passwordless-revoke.hook` deletes every temporary grant before any omarchy-settings upgrade or removal. Affected sentences: the fix's `sudo rm -f /etc/sudoers.d/99-omarchy-nopasswd-$USER` (wrong file name on 4.5.0, so it removes nothing), "15 minutes by default when no argument is given", and "the timer is the only thing that ends the grant on its own". Replace the rm with `omarchy-sudo-passwordless --disable`, and add that a "Permanently" grant exists and is not cleared at boot. Migration 1788163635 handles legacy grants. Confirmed from the script.

4. `update-y-hangs-orphan-or-reboot-prompt` (omarchy-core, corrected), the fix for releases before 4.5.0. The fix says "find the waiting `gum` and kill it. Killing it answers no" and uses `pkill -f`, which sends SIGTERM. This repository's CLAUDE.md records a measurement on 2026-10-18 that under gum 2.0.2 a SIGTERM makes `gum confirm` exit 0, which is yes, and that a SIGTERM watcher rebooted both VMs. gum 2.0.2-1 is what this workstation has installed.
